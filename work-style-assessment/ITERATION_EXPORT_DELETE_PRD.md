---

## 一、迭代背景与目标

### 1.1 背景

当前工作风格测评系统已上线运行，HR 可以在后台查看候选人的测评结果。但存在以下痛点：

1. **无法导出结果**：HR 只能在系统中查看，无法将测评报告导出为文档分享给业务负责人或候选人
2. **无法删除单条记录**：测试数据或错误数据只能通过"清空所有数据"功能处理，无法精准删除

### 1.2 迭代目标

- **导出功能**：为测评结果详情页添加导出按钮，支持导出为 Word（.docx）和 PDF（.pdf）格式
- **删除功能**：在测评结果列表页为每条记录添加删除按钮，支持单条精准删除
- **保持现有逻辑**：不改变任何算分逻辑、评分规则、维度定义或文案生成规则

### 1.3 成功指标

- 100% 已完成的测评结果可成功导出为 Word/PDF
- HR 能在列表页无误删除指定记录，刷新后不再出现
- 无用户投诉导出内容与页面展示不一致

## 二、功能需求详述

### 2.1 导出功能

#### 2.1.1 入口位置

**详情页**（`/hr-admin/[id]`）：
- 位置：候选人信息卡片右上角
- UI：单个「导出」按钮，点击后展开下拉菜单：
  - `导出为 Word`
  - `导出为 PDF`

**列表页**（`/hr-admin`，可选增强）：
- 在每行记录的操作列中添加「导出」按钮

#### 2.1.2 导出内容规范

导出的 Word/PDF 内容必须与详情页展示的数据完全一致：

1. **标题区**
   - 标题：`工作风格测评结果`
   - 候选人姓名、应聘职位、测评日期
   - 提交编号（可选）

2. **总体结果**
   - 综合评分（读取现有算分结果）
   - 匹配度等级（读取现有评级）
   - 评语文本（读取现有评语）

3. **维度得分**
   - 表格展示：维度名称、得分、等级、说明
   - 三个维度：
     - 内在能量 & 弹性指数
     - 防御性 & 攻击风险指数
     - 团队协作倾向

4. **页脚信息**
   - 报告生成时间
   - 简短免责声明（可选）

#### 2.1.3 文件命名

格式：`工作风格测评_候选人姓名_职位_YYYYMMDD-HHmm.{docx|pdf}`

示例：`工作风格测评_张三_前端工程师_20260521-1530.pdf`

#### 2.1.4 交互流程

1. 点击「导出」按钮 → 展开菜单
2. 选择「导出为 Word」或「导出为 PDF」
3. 按钮进入 loading 状态
4. 成功：触发浏览器下载，轻量提示"报告已生成，正在下载…"
5. 失败：提示"导出失败，请稍后重试或联系管理员"

#### 2.1.5 约束条件

- 所有内容来自当前详情页已展示数据，**不新增任何计算逻辑**
- 不改变算分规则、维度定义、阈值或评语生成逻辑
- 导出的内容与页面展示必须字段一一对应

---

### 2.2 删除功能

#### 2.2.1 入口位置

**列表页**（`/hr-admin`）：
- 在每行记录的操作列中添加「删除」按钮
- 位置：「查看详情」按钮之后

#### 2.2.2 删除交互

1. 点击「删除」按钮
2. 弹出确认对话框：
   - 标题：`确认删除该测评记录？`
   - 内容：`删除后该记录将从列表中移除，不再对 HR 可见。`
   - 按钮：「取消」（默认） / 「确认删除」（红色危险按钮）
3. 确认删除后：
   - 按钮进入 loading 状态
   - 成功：该行从列表消失，顶部 Toast 提示"已删除 1 条测评记录"
   - 失败：Toast 提示"删除失败，请稍后重试"

#### 2.2.3 删除类型

- 采用**物理删除**（从 localStorage 中移除记录）
- 删除后无法恢复（符合当前数据存储方式）

## 三、技术实现方案

### 3.1 技术栈选择

**导出功能依赖**：
- Word 导出：`docx` 库
- PDF 导出：`jspdf` + `jspdf-autotable` 或 `pdfmake`

**UI 组件**：
- 下拉菜单：可使用 Tailwind CSS 实现，或引入 headlessui
- 确认对话框：自定义 Modal 组件或使用原生 confirm（快速实现）

### 3.2 文件结构

```
work-style-assessment/
├── utils/
│   ├── export.ts          # 新增：导出工具函数
│   └── storage.ts         # 已有：存储工具（已包含 deleteSubmission）
```
